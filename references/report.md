# 报告编译与审校

把冻结的综合裁决和评分卡编译成一份读者报告。内部过程可以细密，最终文字必须清楚、直接、有判断力；报告不复制流程术语，不把50条扫描记录倾倒给读者。

## 一、固定呈现顺序

审计说明放在标题下方，不编号。正文章节始终使用下列固定编号：

```markdown
# 文本审计：[标题]

> **审计说明**：[对象、范围、必要核查边界与使用限制]

## 1. 结论速览
- **综合评分：X.X/10** —— [整篇文本的质量解释]
- **核心[论证／解释／信息／行动]裁决：[状态]** —— [成立到哪里、卡在哪里]
- **本报告结论的把握度：[高／中／低]** —— [证据边界]

## 2. 总体结论

## 3. 六维评估

## 4. 文章行文骨架

## 5. 重点审计
### 5.1 [由实际发现命名]

## 6. 其他关键发现
### 6.1 [有内容的六维名称]

## 7. 分析收束：[自然、有意义的全文机制标题]

## 8. 修改建议
### 8.1 修改时应当保留
### 8.2 必须修改
### 8.3 重点修改
### 8.4 表达优化

## 9. 关键事实核查

## 10. 来源
```

固定编号用于导航，不产生条数、篇幅或正反内容配额。某节没有实质内容时，保留编号并用一句明确说明本次无新增发现、无需外部核查或未使用外部来源；不为填栏目制造内容。

## 二、审计说明与结论速览

审计说明面向读者，说明审计了什么、必要的事实核查做到哪里、哪些对象不在当前材料范围内。不要单独写“事实核查部分完成”，也不要暴露`partial`、阶段状态或运行术语。

结论速览严格区分三件事：

- **综合评分**评价整篇文本的总体质量；
- **核心任务裁决**评价最主要的论证、解释、信息或行动是否成立；
- **本报告结论的把握度**评价本次审计结论有多稳，并立即解释证据边界。

三行都只加粗“变量名+结果”，破折号后的解释保持普通字重。“部分成立”只能修饰具体核心任务，不能作为整篇文章的最终等级。综合评分后必须有一句真实解释，不写空泛等级。

## 三、六维评估

读取 [scoring.md](scoring.md)，报告只呈现三列：

```markdown
| 维度 | 得分 | 裁决 |
|---|---:|---|
| 任务与成效 | X.X | ... |
| 事实与材料 | X.X | ... |
| 推理与判断 | X.X | ... |
| 结构与推进 | X.X | ... |
| 语言与表达 | X.X | ... |
| 视角与边界 | X.X | ... |
```

裁决不是一句技术标签。它应简洁说明主要成立处、决定性限制以及为何落在这个分数，可以根据实际复杂度写一至数句。不要显示承重性质、内部置信度、详细落点、G1/G2或触发状态。

六维表让读者看到不同评价坐标，详细正文仍由实际发现组织；不要为了让每个维度都“展开”而复制同一问题。

## 四、层级式行文目录树

骨架回答正文按什么顺序写了什么、各部分属于哪个上层单元、承担什么行文作用。它不是作者思考模型，也不是报告自己的分析框架。

先在树上方用一句话给出最关键的结构判断，再使用`\u2502`、`\u251c─`、`\u2514─`组成层级式文本目录树。一级节点沿原文顺序编号，通常保持2—3级；二级节点说明主要内容，用“提出总体评价”“建立评价标准”“转入人物分析”“收束并扩大判断”等简短作用词显示逻辑层级。

```text
结构判断：[读图时最应注意的行文特征]

全文行文骨架
│
├─ 1. [一级阶段]｜[行文作用]
│  ├─ [主要内容]
│  └─ [怎样承接或转向]
│
├─ 2. [一级阶段]｜[行文作用]
│  └─ [主要内容]
│
└─ 3. [一级阶段]｜[行文作用]
   └─ [收束方式]
```

骨架以目录同步全文，以层级表示归属，以简短作用词说明推进。不在骨架中提前展开完整的审计机制、复杂回流或因果网络。

## 五、重点审计

重点审计不只写“问题”，而是呈现最能改变总裁决的发现。它可以是决定性缺陷、直接反例、内部矛盾、外部核查所得、被忽略的竞争解释，也可以是真正改写评价的长处。

按对象、依赖链或作用后果组成动态问题簇，不按六维平铺。每个问题簇根据需要说明：原文做了什么、哪一步成立或失效、证据或反例是什么、最强竞争解释如何影响判断、它为什么改变总裁决。字段不必机械齐全，论述顺序由问题本身决定。

不因为某个材料已在总体结论、六维裁决或分析收束中出现就强行删除。只要它在不同模块中正在回答不同问题，必要的重述就是论述的一部分。

## 六、其他关键发现

这一节承接全面扫描中有意义但不足以成为重点问题簇的发现，放在重点审计之后，并按六维归类逐条写。它们不必为总裁决服务；一个有价值的反例、措辞问题、局部优点、结构细节或边界提醒，被清楚呈现本身就有价值。

不规定每个维度几条，不追求维度之间的对称、等长或平衡感。某个维度可以只有一条，也可以有多条；只显示真正有内容的维度。每条的长度由发现的重量决定，宁可把一条讲明白，也不把它压成扫描笔记式提示语。不展示全部50条，但也不为了显得简洁而埋掉独立有价值的观察。

## 七、分析收束

这一节是详细分析结束时的机制层小结。使用“分析收束：[自然标题]”的标题形式，说明多个局部现象共同由什么起点产生、怎样持续作用、最终带来什么跨局部结果。

它可以带回前文材料，不必为了表面不重复而割断论述。但必须真正回答“这些局部为什么会在同一篇文本中持续同向”；若没有成立的跨局部机制，本节直接说明本次不将局部问题上升为统一机制。

## 八、修改建议

“修改时应当保留”负责划定修改边界，只写文本中值得保留的事实、观察、表达、结构、能力或认知增量。不为礼貌制造优点，也不把“作者关注了一个议题”自动算成价值。

其余建议按读者语言组织：

- **必须修改**：不处理会使中心任务、主要结论或实际使用失效；
- **重点修改**：显著影响可信度、解释力、价值或说服；
- **表达优化**：局部清晰度、节奏、用词或呈现优化。

只说明处理对象、理由和完成标准，不自动改写正文。公开报告不显示P0/P1/P2。

## 九、关键事实核查与来源

第9节记录会影响文章可信度、主要解释或使用决定的关键事实，不暗示穷尽全文所有可搜索名词。已核实、核实为错误、无法独立核实、属实但证明力有限、以及根本不是可直接核验命题的承重声明，都应如实显示。

使用三列表：

```markdown
| 事实声明 | 核查结论 | 说明 |
|---|---|---|
| [原文实际提出的声明] | [属实／错误／尚不能独立核实／属实但证明力有限／并非可直接核验事实] | [一句说明依据、边界及它如何影响文章判断] |
```

不要把多个不同声明压成一个“核查方向”。表中的说明可以提及来源名称，但不放可点击网址。所有可点击链接统一放在第10节“来源”，正文和重点审计中只用来源名称。

## 十、报告风格

正式报告应当清醒、直接、有锋芒。明确判断不应被防御性限定和面面俱到的铺陈淹没；谨慎应体现在边界准确，而不是把每句话都写成折中意见。允许根据问题本身的重量自由安排节奏、长短和语气，不使用统一的论证句式。语言可以有批评力度、鲜明个性和利落标题，不因为表达尖锐就主动软化；唯一边界是不能超过证据。中间过程负责滴水不漏，最终报告负责让真正重要的判断清楚地刺出来。

这是整体风格要求，不是句式模板。不要规定每段必须先结论、再证据、再影响；也不要用“当然／但也要看到／不过”反复制造四平八稳。

## 十一、受控迭代

### R0 覆盖稿

生成`working/05-report-coverage-draft.md`。把决定总裁决的发现、重要补充发现、六维裁决和必要事实全部安置，允许暂时冗长。每项入选发现单独登记正式落点，不先把一个维度的多项发现压成一句摘要。允许一个发现在不同模块被带回，只要覆盖稿说明它此处回答的是什么问题。

### R1 读者稿

在不改变冻结裁决和评分的前提下，合并、压缩、重排和结构化，生成`report.md`。可以改变表达，不可无声改变判断。

### 报告审校

生成`working/06-report-editorial-review.md`并检查：

- 审计说明是否位于标题下且不编号；
- 1—10节是否标题准确、顺序固定、没有跳号；
- 结论速览是否统一只加粗变量与结果；
- 综合评分、核心任务裁决和把握度是否各司其职；
- 总体结论是否先于六维和骨架；
- 六维是否只有得分与充分裁决，没有技术列；
- 骨架上方是否先给出结构判断，目录树是否同步正文顺序、层级归属和行文作用；
- 决定性发现是否进入重点审计，其他有价值发现是否获得补充落点；
- 其他关键发现是否因真实重量自然展开，而非六维各凑相同条数或压成过短提示；
- 分析收束是否真正解释跨局部机制，或如实说明不上升；
- 必要的跨模块重述是否各自回答了不同问题，而不是只做无信息增量的复制；
- 修改时应当保留的内容是否已放入第8节，修改建议是否使用读者语言；
- 关键事实核查是否逐条呈现事实声明、核查结论和一句说明，并包含会影响判断的未核实声明；
- 正文是否没有裸露的技术状态、G1/G2、P0/P1/P2与行内网址；
- 报告、评分卡、综合稿和事实状态是否一致；
- 文风是否直接、有力、有锋芒，但没有超过证据。

审校通过时写`- Result: passed`。若只是呈现问题，迭代读者稿；若裁决或证据矛盾，退回综合阶段重新冻结，不在报告中静默修改。
