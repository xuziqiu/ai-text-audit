# XZQ文本审计回归测试

使用彼此隔离的真实文本验证开放性、覆盖率、复核深度和报告可读性。测试Agent只获得本Skill、待检正文和普通用户请求，不获得预期答案、旧报告或本次设计讨论。

## 必测类型

1. **复杂解释或议论文本**：多条解释链、事实与价值交错，验证重点审计不会退化为六维平铺。
2. **优质文本**：验证不会为了证明认真而制造问题，能够明确判断成立。
3. **严重失效文本**：验证能直接重判，不添加礼貌性优点。
4. **混合文本**：叙述、解释、评论并存，验证不先按单一体裁路由。
5. **非评论任务文本**：通知、说明或工作报告，验证不强加“核心洞察”和议论文标准。
6. **简单完整文本**：验证内部责任完成但成品不展开空栏目。
7. **初读反转样本**：第一印象容易误导，验证综合稿能够保留并解释修正而非回写初读。
8. **开放发现样本**：决定性问题不属于常见事实、逻辑、语言标签，验证扫描仍能记录并追查。
9. **高表达低可靠样本**：语言和结构优秀但承重事实或推理失效，验证总分不能绕过硬门槛。
10. **朴素可靠样本**：表达普通但任务、事实和推理成立，验证不会因缺少华丽文风而被误判失效。
11. **评分不适用样本**：某个维度真实不存在，验证N/A归一化而非强行填分。

## full_trace检查

- 初读文件确实先完成并被冻结；
- 行文骨架是正文推进，不是思考模型；
- 内容地图没有强迫所有文本形成主张链；
- 全面扫描按原文顺序保留命中，后续驳回也没有删除；
- 完整文本的全面扫描含至少50条有原文依据、编号唯一的候选观察；数量没有演变为类别配额或报告条数；
- 重点复核线程由发现驱动，没有固定数量或字段配额；
- 事实来源与事实证明作用分开；
- 综合稿明确回看初读判断；
- 审计说明位于标题下且不编号，正文1—10节标题固定、顺序正确、没有跳号；
- 结论速览只加粗变量和结果，三项解释字重一致；
- 骨架上方先给出一句结构判断，骨架使用`\u2502`、`\u251c─`、`\u2514─`组成层级式行文目录树；
- 目录树沿原文顺序同步主要阶段，用二至三级表示归属和行文作用，不把审计机制或作者思考模型当骨架；
- 覆盖稿为决定性发现指定唯一正式落点；
- 报告审校记录`Result: passed`并检查重复与信息增量；
- 报告按决定性问题簇组织，并用按六维归类的其他关键发现承接值得呈现的次级观察；
- 其他关键发现没有凑成每维相同条数，也没有把所有发现压成相同长度的简短提示；
- 分析收束用自然标题说明跨局部机制，允许因回答不同问题而必要地带回前文材料；没有成立机制时如实说明不上升；
- “修改时应当保留”已并入第8节，没有独立的“真正保留的部分”章节；
- 关键事实核查使用“事实声明／核查结论／说明”三列，不只展示找到来源的项目；
- 报告关键判断可追溯到中间文件；
- 评分只使用综合稿中已有发现，没有反向控制扫描或复核；
- `scorecard.json`与报告十分制总分、六维裁决、综合质量、核心任务裁决和把握度一致；公开报告不泄露内部门槛字段；
- 同一底层问题没有在多个维度完整重复计分；
- 计算质量带受到任务、可靠性、未决事实和边界门槛约束；
- 其他Skill与历史版本都没有被修改或混用。

## 失败模式

- 初读快照事后重写成最终结论；
- 全面扫描只寻找支持初读的证据；
- 全面扫描不足50条，或为了凑数制造与原文无关的同义改写；
- 先分维度再决定能看见什么；
- 把所有文本强制转成主张链；
- 重点复核成为第二份问题清单；
- 综合只是合并和排序；
- 同一病灶在事实、逻辑、语言、边界中重复计重；
- 最终报告省略行文骨架或只交付执行摘要；
- 总体结论被放在骨架之后；
- 正文章节没有固定编号、出现跳号或因本次无内容而删除导航位；
- 骨架只是纯目录，没有表示层级归属和行文作用；
- 把骨架做成复杂因果网络、审计机制或作者心理模型；
- 覆盖稿直接作为最终报告交付，没有读者稿压缩；
- 六维表只有技术标签，或复制重点审计正文，而不是给出足以解释分数的裁决；
- 固定全文审计与重点审计重复同一发现；
- 50条扫描记录被原样倾倒进最终报告；
- 其他关键发现每维刚好相同条数，或只剩下没有完整判断的短句；
- 事实核查只列已找到来源的几项，隐去会影响判断的未核实或不可核验承重声明；
- 先看评分维度再决定全面扫描要找什么；
- 语言或结构高分把承重事实错误平均成通过；
- 因审计者没有执行事实核查而直接扣文章分，而不是降低置信度和标记临时状态；
- 同一问题在任务、推理、结构、语言和边界中重复重罚；
- 用开放性为无证据推测作者动机辩护；
- 审计结束后自动改稿。

## 固定前向回归

使用奥特曼比较文章作为第一条完整回归，但测试运行只能读取冻结原文，不复制旧报告或旧中间稿。除通用检查外，验证能否发现并正确安置这一类材料冲突：正文以“严肃风格注定不受欢迎”为普遍解释，同时把盖亚类比为风格严肃的赛文；若外部人气材料显示赛文本身长期高人气，这一反例应进入关键发现并迫使结论收窄，而不能消失在事实附录或六维表中。

## 验证顺序

1. 运行`scripts/validate-text-audit-skill.ps1`；
2. 运行`skill-creator/scripts/quick_validate.py`；
3. 测试管理脚本的初始化、完成门、哈希恢复和越界路径保护；
4. 使用真实文本完成至少一次full_trace前向运行；
5. 对同一冻结文本、评分契约和证据范围重复评分；单维漂移超过0.5分或十分制总分漂移超过0.5分时复核原因；
6. 检查报告、评分卡与中间文件后再决定是否同步到全局目录。
