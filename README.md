# AI Text Audit

一套面向文章、审计卡片与长文本质量复核的 Codex Skill。

它不从“这段话是不是 AI 写的”开始，而是把可见现象、背景解释、全文模式和修改决定分开处理，避免合理的来源说明提前冲销真实的阅读感受。

> 先识别现象，后解释原因，最后综合判断。

## 它解决什么

常见的文本审计容易把观察与解释混在一起：一个表达只要“语义合理”“符合正式体裁”或“成熟作者也可能这样写”，就可能被提前排除。结果是局部候选消失，跨段落、跨章节的整体模式也无法进入最终判断。

AI Text Audit 先保存读者能够直接看到的语言与结构现象，再结合写作目标、文本功能和来源信息校准严重性与修改方式。

流程的核心不是固定轮次，而是判断顺序：背景可以改变怎么改，不能改变读者已经看见了什么。

## 审计如何展开

1. **记录可见现象。** 暂时不让背景解释参与排除，保留清楚命中与边界候选。
2. **分别记录判断维度。** 不用一个总分掩盖不同问题。
3. **加入背景校准。** 结合体裁、功能、来源与实际工作过程，调整严重性、来源解释和修改方案。
4. **检查全文模式。** 观察局部候选是否跨段落、跨章节累积。
5. **停在作者决策门。** 审计不会自动改写，也不等于发布许可。

## 四轴记录

重要候选分别记录四个维度：

- `现象强度`：这种语言或结构特征有多明显。
- `功能支付`：它是否承担必要的说明、论证或组织功能。
- `AI感贡献`：它对全文的机械感、模板感或过度完成感贡献多大。
- `来源贡献`：现有背景能在多大程度上解释它为什么出现。

一个表达可以功能成立、来源正常，同时仍然增加整篇文章的 AI 感。四轴记录保留这种差异。

## 它会检查什么

除局部表达外，Skill 会检查跨段落与全文模式，例如：

- 显性导航过密；
- 否定—转折—限定句群反复出现；
- 平衡补丁与递进式复述；
- 同构验证与段落自动闭环；
- 高密度关系管理；
- 全文过强的“任务完成感”。

这些现象不是 AI 来源证明。它们只是需要被记录、解释，并交由作者判断是否影响阅读的文本事实。

## 决策门

审计完成后不会自动重写文章。结果应同时呈现：

- 原文或被审计对象；
- 可见现象与综合诊断；
- 支持修改和保留原文的理由；
- 不同选择可能带来的后果；
- 可供作者选择的具体方案。

只有用户明确选择改写，流程才进入下一版。内部自检也不等于最终发布许可。

## 安装

将仓库克隆到个人 Skill 目录：

```powershell
git clone https://github.com/xuziqiu/ai-text-audit.git "$HOME/.agents/skills/ai-text-audit"
```

Codex 通常会自动发现新 Skill。如果没有出现，重启 Codex。

## 使用

在 Codex 中明确调用：

```text
$ai-text-audit 审计这篇文章。先记录可见现象，不要让背景解释提前排除候选。
```

当任务描述与 Skill 的适用范围一致时，Codex 也可以自动选择它。

## 边界

- 它不是 AI 检测器，也不提供作者身份或生成来源证明。
- 它不以规避检测或机械降低某个指数为目标。
- 它不会因为发现问题就自动改写文章。
- 它不会把自检结果当成最终发布批准。
